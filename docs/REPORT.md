## 2. Abstract

Large Language Models (LLMs) routinely hallucinate when answering questions over user-uploaded documents—conflating parametric pre-training memory with uploaded context and fabricating plausible yet unsubstantiated assertions. In domain-specific document question answering (legal, scientific, medical, and academic), confident fabrication is far more detrimental than an explicit refusal. 

**DocChat v2.0** resolves this foundational vulnerability through a multi-tiered architecture combining:
1. **Mathematical Retrieval Gating & Strict Conditioning**: A Cosine similarity gate ($S \ge 0.10$) and constrained system prompt enforce that the LLM operates strictly within retrieved document context and issues an unambiguous refusal when facts are absent.
2. **Agentic RAG Pipeline (Thinking Mode)**: Query routing, parallel chunk relevance grading (`ThreadPoolExecutor`), and adaptive query rewriting dynamically optimize retrieval before context assembly.
3. **Open Knowledge Filtering & Fusion (OKF) Engine**: A deterministic engine providing noise filtration, token-level Jaccard semantic deduplication (threshold = 0.82), cross-source conflict detection, and provenance-tagged context synthesis.
4. **Two-Layer Hallucination Audit**: Every response undergoes sentence-level cosine grounding (Layer 1) and structured claim-level verification (Layer 2), returning groundedness scores, risk assessments, and verbatim hallucination spans highlighted in the user interface.
5. **Decoupled Modern Stack**: An asynchronous **FastAPI** backend with Server-Sent Events (SSE) streaming pairs with a **Next.js 16 / React 19** Claude/ChatGPT-style canvas, providing dark/light themes, KaTeX math typesetting, drag-and-drop document vaults, and PBKDF2-authenticated multi-tenant isolation.

Automated evaluation across 66 ground-truth questions and five diverse domain corpora demonstrated **93.0% in-document accuracy**, **100.0% out-of-document refusal rate**, **100.0% prompt injection neutralization**, and an average end-to-end response time of **826 ms**.

## 3. Introduction & Problem Statement

Large language models represent a paradigm shift in natural language comprehension; however, their non-deterministic nature and susceptibility to extrinsic hallucinations ([Ji et al., 2023](https://arxiv.org/abs/2202.03629)) severely restrict their utility as trustworthy document intelligence systems. When queried regarding specialized user documents, standard models frequently confabulate dates, statistics, and citations with uniform authoritative confidence.

DocChat addresses this challenge via three non-negotiable architectural axioms:
1. **Refusal Over Fabrication**: When uploaded documents lack the requisite factual substrate to answer an inquiry, the system must categorically refuse rather than synthesize speculative approximations.
2. **Provenance & Attributions**: Every statement generated by the assistant must be traceable to specific document excerpts surfaced transparently to the user.
3. **Explicit Epistemic Uncertainty**: Rather than presenting text as unconditionally authoritative, the system measures and visualizes its own groundedness percentage, flagging unverified phrases with visual span alerts.

## 5. Objectives & System Scope

### 5.1 In-Scope Deliverables
- Ingestion and chunking of `.pdf`, `.docx`, `.txt`, `.csv`, `.md`, and `.json` documents up to 25 MB.
- Local vector database persistence in ChromaDB with multi-tenant partitioning (`where={"user_id": user_id}`).
- Pre-retrieval gating using normalized Cosine similarity ($S \ge 0.10$).
- Agentic RAG (Thinking Mode) with query routing, parallel chunk relevance grading, and adaptive query rewriting.
- Open Knowledge Filtering & Fusion (OKF) with Jaccard deduplication and conflict analysis.
- Real-time token and thought streaming over Server-Sent Events (SSE).
- Two-layer hallucination audit surfacing groundedness percentages, risk metrics, and verbatim span highlights.
- PBKDF2-HMAC-SHA256 user authentication with SQLite WAL persistence.
- Next.js 16 / React 19 Claude/ChatGPT-style responsive interface.
- QLoRA fine-tuning infrastructure (420-example dataset with 33.3% refusal ratio).
- Multi-container Docker deployment with pre-baked model weights.

### 5.2 Out-of-Scope (Future Work)
- Hardware-accelerated Optical Character Recognition (OCR) for image-only scanned PDFs (Tesseract integration planned).
- Native layout-aware parsing for arbitrary multi-column financial balance sheets.
- Multi-lingual cross-lingual semantic alignment (requires multi-lingual embedding switch).

## 7. RAG Pipeline & OKF Methodology

### 7.1 Ingestion & Chunking
1. **Extraction**: `extract_text()` processes `.pdf` (pypdf), `.docx` (python-docx), and plaintext files with encoding fallbacks (UTF-8, Latin-1, ASCII replace).
2. **Chunking**: LangChain `RecursiveCharacterTextSplitter` segments text into 500-character windows with 50-character overlaps. Fragments under 50 characters are filtered out.
3. **Embedding**: `sentence-transformers/all-MiniLM-L6-v2` produces 384-dimensional dense vectors with unit normalization (`normalize_embeddings=True`).
4. **Storage**: Vectors and metadata (`source`, `user_id`, `chunk_id`) are stored in ChromaDB's persistent collection `documents`.

### 7.2 Retrieval & The Retrieval Gate
In Simple Mode, user queries are embedded and compared against the vault collection using cosine similarity. The retrieval gate calculates:
$$S = 1 - \frac{D^2}{2}$$
If the top similarity score is below `SIMILARITY_THRESHOLD = 0.10`, the query is flagged as ungrounded, and the system emits an immediate grounded refusal without LLM generation.

### 7.3 Agentic Pipeline (Thinking Mode)
1. **Query Router (`_route_query`)**: Uses low-temperature classification to distinguish between inquiries requiring document search (`retrieve`) and general conversational chit-chat (`direct`).
2. **Parallel Chunk Grader (`_grade_chunks`)**: Employs parallel LLM calls (`ThreadPoolExecutor`, 5 workers) to evaluate retrieved chunks against the query. Only relevant chunks pass to the fusion stage. Grading defaults fail-closed (`False`) on error to prevent noise leakage.
3. **Query Rewriter (`_rewrite_query`)**: If all chunks fail grading, the query is rewritten into a keyword-dense search term and ChromaDB is re-queried.

### 7.4 Open Knowledge Filtering & Fusion (OKF) Engine
The OKF engine applies deterministic post-retrieval processing:
- **Noise Elimination**: Removes fragmented artifacts (< 30 characters or high punctuation density).
- **Semantic Deduplication**: Applies token-level Jaccard similarity filtering ($J(A, B) \ge 0.82$) across multi-document chunks to eliminate redundancy.
- **Cross-Source Conflict Detection**: Scans numerical metrics across different documents and alerts the user if conflicting figures are detected.
- **Provenance-Tagged Context Assembly**: Generates unified context blocks annotated with source tags (`[Source: filename]`).

## 8. Fine-Tuning Infrastructure (LoRA / QLoRA)

### 8.1 Synthetic Dataset Generation (`backend/generate_dataset.py`)
To instill negative constraint learning, 420 structured `{instruction, input, output}` pairs were generated across the multi-domain corpus:
- **Composition**: 280 grounded answerable pairs (66.7%) + 140 unanswerable refusal pairs (33.3%).
- **Format**: LLaMA-3.2 chat template format (`<|start_header_id|>...<|end_header_id|>`).

### 8.2 QLoRA Configuration (`notebooks/phase3_finetuning.ipynb`)
- **Base Model**: `meta-llama/Llama-3.2-3B-Instruct`.
- **Quantization**: 4-bit NormalFloat (NF4) with double quantization via `bitsandbytes`.
- **LoRA Hyperparameters**: Rank $r=16$, alpha $\alpha=32$, dropout $0.05$. Target modules: `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`.
- **Training Harness**: Hugging Face `SFTTrainer` with `paged_adamw_8bit` optimizer and cosine learning rate scheduler ($2 \times 10^{-4}$).

## 9. Two-Layer Hallucination Detection & Audit

```
Generated Answer + Reference Context
                  │
                  ├──▶ Layer 1: Sentence-Level Cosine Grounding (all-MiniLM-L6-v2)
                  │             Average vector similarity: Question vs. Chunks (0-100%)
                  │
                  └──▶ Layer 2: LLM Claim-Level Verification (Groq LPU)
                                1. Atomic claim extraction
                                2. Verification of textual support
                                3. Verbatim hallucinated span extraction
                                │
                                ▼
                     Composite Audit Payload
                     - Groundedness Score (0 - 100%)
                     - Hallucination Risk (0 - 100%)
                     - Verbatim Spans for Inline UI Highlighting
```

- **Layer 1**: Evaluates vector alignment, detecting general off-topic drift.
- **Layer 2**: Uses a primary single-pass structured JSON audit on the Groq LPU with parallel multi-worker fallback.
- **UI Highlighting**: Detected unsupported spans are tagged in the response JSON and rendered in the frontend message bubble with visual warning badges.

## 10. Results & Quantitative Evaluation

Automated evaluation was conducted using `tests/scripts/run_tests.py` against 66 ground-truth test questions across five domain corpora (`climate_change.txt`, `space_missions.txt`, `python_programming.txt`, `mediterranean_diet.txt`, `countries.csv`).

### 10.1 Key Benchmark Results

| Metric | Pre-Fix Baseline | Final Production Result (v2.0) | Target | Outcome |
|---|---|---|---|---|
| **In-Document Answer Accuracy** | 93.0% (40/43) | **93.0%** (40/43) | > 85.0% | ✅ Exceeded |
| **Out-of-Document Refusal Rate** | 0.0% (0/19) ⚠️ | **100.0%** (19/19) | > 90.0% | ✅ Exceeded |
| **Edge-Case / Greeting Handling**| 75.0% (3/4) | **100.0%** (4/4) | 100.0% | ✅ Met |
| **Prompt Injection Blocking** | 100.0% (11/11) | **100.0%** (11/11) | 100.0% | ✅ Met |
| **Average End-to-End Latency** | ~2,500 ms | **826 ms** | < 2,500 ms | ✅ Exceeded |
| **Retrieval Gate Precision** | 80.0% | **100.0%** | > 95.0% | ✅ Exceeded |

### 10.2 Analysis of the Refusal Fix
The initial test run exhibited a 0% refusal rate due to two compounding factors:
1. The original prompt lacked strict negative refusal instructions.
2. The chunk grader defaulted to `True` (keep chunk) on parsing errors, allowing irrelevant chunks to pass into the prompt context.

Flipping the chunk grader error default to `False` (fail-closed) and rewriting the prompt constraint to mandate explicit refusal raised the out-of-document refusal rate from **0.0% to 100.0%** across all 19 negative test cases without impacting the 93.0% in-document accuracy.

## 11. Known Limitations & Technical Constraints

1. **Scanned Image PDFs**: Image-only PDF pages without embedded text layers cannot be extracted without an OCR preprocessing pipeline (Tesseract integration planned).
2. **Complex Multi-Column Tables**: Multi-column PDF layouts without explicit cell dividers may be linearized in reading order by `pypdf`.
3. **Cloud API Dependency**: Primary inference relies on the Groq Cloud API; air-gapped deployments require swapping to a local vLLM or Ollama instance.

## 13. Conclusion

DocChat demonstrates that Retrieval-Augmented Generation can be transformed from an unreliable, hallucination-prone system into a rigorous, verifiable document intelligence platform. By enforcing mathematical retrieval gating, agentic query routing, Open Knowledge Filtering (OKF), two-layer hallucination auditing, and client-side span highlighting, DocChat establishes a new benchmark for trustworthy document QA.

The transition to a decoupled FastAPI backend and Next.js 16 Claude/ChatGPT-style web application delivers enterprise reliability, sub-second latency, and seamless multi-tenant isolation, fulfilling all requirements of the BTech final-year project.
